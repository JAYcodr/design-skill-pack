# 逐屏稿：多屏设计先排内容，再写代码

> 多屏设计最常见的失败不是首屏，是往下每一屏长得一样——小标题 + 三张卡片，重复到底。逐屏稿逼你在写 CSS 之前回答："这一屏靠什么撑住？"

**什么时候用**：页面 ≥5 屏（一屏 = 一个视口高），或内容区块超过 3 个——落地页、官网、长页、多屏 demo。单屏 hero / 单幅海报可跳过。

## 模板

存项目里的 `screens.md`，每个设计方向一张。表头就这五列：

| # | 这屏讲什么（对应题面哪条内容） | 形式 | 这一屏的主角 | 素材来源 |
|---|---|---|---|---|
| 1 | 一句话定位 | 断言首屏 | 巨字 "带。" + 雨天背景 | 纯 CSS |
| 2 | 产品的核心机制 | 可玩演示 | 拖拽滑块，画面跟着变 | 真数据 |
| 3 | 为什么可信 | 前后对比 | 同构两屏只差一处 | 截图 |
| … | … | … | … | … |

## 四条规则

1. **题面要求的每条内容都要落到某一屏**——写完回勾，缺段是低分塌陷第一位。
2. **相邻两屏不用同一种形式**——治"往下全一样"。
3. **每屏主角写不出来，就是这屏还没设计**——先想清楚再写 HTML。
4. **首屏三秒**：没看过这个项目的人，三秒内看得出"这是什么、给谁"吗？题材里独有的东西出现在第一眼里了吗？

## 形式菜单（按内容挑，不按顺序挑）

| 形式 | 适合讲什么 | 一句话做法 |
|---|---|---|
| 断言首屏 | 一句话定位 | 一句标题 + 一个主角素材 + 一个动作 |
| 产品界面 + 标注 | 产品长什么样 | 画出真实界面，细线引出 2–3 条说明 |
| 可玩演示 | 核心机制 | 一个滑块/开关/拖拽，动一下画面跟着变 |
| 数据即图像 | 一个关键数字或一组数 | 画成刻度、面积、长度、密度，不做数字卡片 |
| 前后对比 | 以前/现在、A/B | 两幅同构画面，只差一处 |
| 剖面 / 地图 | 空间、层级、路线 | 一张贯穿全宽的图，文字标在图上 |
| 时间轴 | 过程、日程、节奏 | 横向刻度，事件挂在刻度上 |
| 大字声明 | 一句最重要的话 | 一屏只放一句，字大到成为画面 |
| 故事长段 | 起因、人、来历 | 窄栏大行距，像一页书，配一张图或一个年份 |
| 图文对开 | 一个功能的展开 | 一半图一半字，下一个功能左右对调 |
| 清单 / 规格表 | 覆盖范围、参数 | 细线表格或两栏清单，不套卡片 |
| 价格对比 | 免费/付费、档位 | 两栏并排，差别逐行对齐 |
| 行动收尾 | 下载、联系、报名 | 一个动作，周围留空 |

页面用到五六种形式是正常的；三屏以上全用同一种，就是没设计。

## 与红线③的关系

逐屏稿是"写之前"的检查，截图自验是"写之后"的检查，两个都要：

- 写前：screens.md 排好每屏的形式与主角；
- 写后：逐屏截图，对照 screens.md 看走样在哪；
- 对不上时改页面或改稿，但两边必须重新对齐再交。

## 验收

- [ ] `screens.md` 存在，页面与它逐屏对得上；
- [ ] 题面内容零缺段；
- [ ] 无相邻两屏同形式；
- [ ] 每屏主角可指认（说不出 = 返工）；
- [ ] 首屏三秒说得清"是什么、给谁"。
