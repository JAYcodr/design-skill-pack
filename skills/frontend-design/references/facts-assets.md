# 事实与资产：概念之前，先把"真的"拿齐

> 模型对"X 是什么、什么时候发布、品牌是什么色"的记忆不可靠。写错事实比不好看严重——不好看是审美问题，写错是硬伤。

**触发**（任一命中就做，不做就是赌）：

- 具名品牌 / 公司 / 产品 / 人物；
- 具体事件、发布状态、版本号、规格、价格、日期；
- 对比、榜单、评测、推荐——**出现几个产品就取几个官方 logo**，不是有就用、没有拉倒；
- 真实项目交付（客户品牌、真实店名、真实产品）。

主题词不算品牌：咖啡、历史、健身不是品牌，别去找"咖啡的 logo"。

## 两个产物

项目根目录下写两份文件，交付时跟着成品一起给：

- `product-facts.md`——所有事实与出处
- `brand-spec.md`——涉及具体品牌时才有

### product-facts.md

| 事实 | 来源（URL / 官方文档 / 截图路径） | 核对日期 | 置信度 |
|---|---|---|---|
| 例：产品 X 于 2026-09-12 发布 | 官方发布页 URL | 2026-11-10 | 高 |

规则：

1. 搜不到就写「未找到」，不猜、不编；
2. 页面上出现的每个数字、日期、版本、价格，都要能在这张表里找到；
3. 交付说明末尾列「未核实项」，让用户知道哪里可能有错。

这一条为什么在问问题之前：事实错了，后面问什么、设计什么都是歪的。常见事故：凭记忆断言某产品"还没发布"，实际四天前已发布，返工两小时。

### brand-spec.md（五步）

1. **问**：用户有没有品牌指南、logo、色值、字体规范？有就直接用。
2. **搜官方**：`<brand>.com/brand`、`brand.<brand>.com`、press kit、官网 HTML 全文。
3. **取资产**（三条兜底，前一条失败立刻走下一条）：官方 SVG/PNG logo → 官网 HTML 里的字体与色值 → 产品截图取色。
4. **取色**：从资产里 grep 所有 `#xxxxxx`，按出现频率排序，过滤黑白灰；**绝不从记忆里猜品牌色**。
5. **固化**：写 `brand-spec.md`，并把色值固化成 CSS 变量（`--brand-*`），页面全部引用变量。

`brand-spec.md` 最小内容：品牌名、官方来源 URL、logo 文件路径、主色/辅色（含出处）、字体、禁用项（如不得改 logo 比例）、核对日期。

## 边界：用于"准确"，不用于"像"

品牌资产解决的是**事实准确**：logo 用官方文件、色值用官方值、产品名一字不差。

它不解决**视觉决策**：版式、材质、概念仍按红线①自己推导；官网怎么排版是参考，按红线②只学"为什么"，不复制外观。把"用了官方色"当成设计完成，是把事实当成了作品。

找不到资产时：交付说明写「未找到官方资产，以下为占位/近似值」，不要假装是官方。

## 验收

- [ ] 页面上每个真实 logo 都有来源文件，不是凭印象画的；
- [ ] 每个品牌色都能在 `brand-spec.md` 里找到出处；
- [ ] `product-facts.md` 覆盖页面全部数字/日期/版本；
- [ ] 未找到的项被明确标出，没有混进正文当事实。
