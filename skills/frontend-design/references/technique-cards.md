# 技法卡 14 张

> 每张卡：来源案例 / **同构性前提** / 适用场景 / 核心机制 / 实现要点 / 禁忌。
> 技法是"可复用的决策模式"，不是"可复制的代码"——复用机制，重新发明材质。
>
> **同构性前提先看，再看别的。**教训来自 CASE-010：mono chip 在 reasonix 是骨架语言（产品是终端 agent，词的形式即词的内容），被挪到灯塔监控题就成了形式借用——技法与概念不同构，执行得再对也是抄。前提不满足，技法就是别人的衣服。

---

## T01 立起时刻

- **来源**：CASE-003 达芬奇飞行器
- **同构性前提**：产品叙事里有"从平面进入立体"的隐喻——草稿成真、想象落地、纸面进入现实。没有这层隐喻，立起只是杂技
- **适用**：需要一个"标志性时刻"的单页 / demo / hero
- **机制**：2D ⇄ 3D 双重读法——摊平时压扁的 3D 零件直接读成纸面草图；立起后草图留在纸上、机器浮在空中。"想象从手稿里立起来"
- **实现要点**：stagger 立起 + 弧线回落；**相机编舞是空间叙事的一部分**（俯瞰读手稿 ⇄ 3/4 侧视看机械，随状态切换滑行；用户一旦拖拽立即交还控制权）
- **禁忌**：没有相机编舞的立起不成立；立起后 2D 层不残留 = 白白放弃双重读法

## T02 仪式化开场

- **来源**：CASE-004 CRT 开机作品集 → CASE-005 八音盒复用验证
- **同构性前提**：使用产品本身有"启动成本/仪式感"——开机、上弦、装填、点燃。产品是即用即走的工具时，仪式是拦路片头，不是礼物
- **适用**：作品集 / 产品介绍 / 任何"正片之前值得一个仪式"的场景
- **机制**：五步全是叙事——①等待态（暗房/已装填）→ ②用户触发（**交互动作的身份 = 叙事动作**：点黑屏=按电源键、拖拽=上弦）→ ③镜头编舞 → ④档案式信息 reveal（`RUN PERSONAL_ARCHIVE.EXE`/打孔纸卷）→ ⑤材质内转场（花屏/纸面吞没）→ 正片
- **实现要点**：开场必须用户亲手触发，不是自动播放的片头；等待态埋"触发后才兑现"的伏笔（铭牌/曲目卡）
- **禁忌**：跳过触发直接播片；转场跳出材质纪律（用通用渐变淡入而非材质固有行为）

## T03 机械因果链

- **来源**：CASE-003 传动链、CASE-005 棘轮
- **同构性前提**：交互对象有真实机械/物理原型（旋钮、发条、齿轮、杠杆）。界面元素没有物理原型（表单、列表、看板）时，硬造因果链是过度工程
- **适用**：一切"机械感/手感"诉求
- **机制**：动效跟随真实因果链，不跟随定时器——曲柄→齿轮 2x 反转→连杆→翼；棘轮只进不退、每 30° 一响、上满 clunk。翼风/齿音由传动相位触发
- **实现要点**：先搞懂真实机制的原理图，再把原理翻译成状态机；反向操作要有真实反噬（棘轮咬住）
- **禁忌**：用 easing 调参假装手感——用户能感觉出来

## T04 冷暖配给

- **来源**：CASE-005 冷月 + 盒内暖灯
- **同构性前提**：叙事里有"点灯/唤醒/温暖降临"事件，冷暖才有配给对象。没有叙事事件的工具页，冷暖只是普通配色方案
- **适用**：register 选定后需要"温度"的场景
- **机制**：全场一个温度，对立温度的光源**配给给叙事事件**——暖光不是氛围，是"开盒=点灯"这个剧情
- **实现要点**：数清楚全场有几路光；每路光报出其叙事身份；没有身份的关灯
- **禁忌**：暖光冷光摊平成氛围照明

## T05 叙事伏笔

- **来源**：CASE-005 铭牌 OPUS № 1 / 盖内曲目卡
- **同构性前提**：页面有"等待态→触发态"两阶段结构。单状态页面没有兑现时刻，伏笔无人认领
- **适用**：仪式化开场、场景化 UI
- **机制**：等待态埋"触发后才兑现"的细节——用户在触发前看到但读不到，触发后回看全对上了
- **实现要点**：真实物件里找伏笔原型（真八音盒都有调名卡）；伏笔必须是材质内原生物件
- **禁忌**：为埋伏笔发明不存在于该材质的物件

## T06 骨架语言

- **来源**：CASE-006 reasonix（纪律派）
- **同构性前提**：产品本身讲一种可识别的语言（终端/乐谱/图纸/电报/处方），骨架字体才有同构对象。产品没有自己的语言体系时，先回红线 1 找概念，别先借别人的 mono
- **适用**：工具型产品页 / 文档站 / 任何"结构层需要性格"的页面
- **机制**：一种字体承担全站结构层，且字体与产品语言同构——JetBrains Mono 做 eyebrow（`$ Features`）、索引（`01 / CACHE-FIRST`）、图注（`fig. 01 —`）、hero 标题里的 mono chip。**词的形式即词的内容**
- **实现要点**：列出全站所有"结构性文本"（眉题/索引/图注/标签），统一交给骨架字体；内容文本用另一套
- **禁忌**：骨架字体与产品语言无关（给烘焙店用 mono）

## T07 单一语义色

- **来源**：CASE-006 reasonix
- **同构性前提**：页面是内容驱动、有明确语义层级。视觉驱动的页面可能连强调色都不该有（007：蓝即底，无强调色）——别把"语义色"当成又一个必须有的小面积点缀
- **适用**：纪律派白底页
- **机制**：唯一强调色只落在**有语义的词/物**上（cheap / the last / 94 contributors / computed 方块 / 主按钮），不给装饰
- **实现要点**：列一张"强调色出现位置"清单，逐个回答"它为什么是这个词"
- **禁忌**：强调色落在装饰元素上；超过一个强调色

## T08 动效预算集中

- **来源**：CASE-006 押一个轮播 / CASE-007 接近零
- **同构性前提**："押一个大的"成立的条件是——那个大动效演示的是产品原理或叙事物件。大动效只是好看（粒子背景、炫技 hero）时，预算越大死得越惨
- **适用**：纪律派；也约束惊艳派（撒胡椒面死）
- **机制**：动效预算三种合法形态——①集中押一个大的（且大动效=产品原理演示）②接近零，靠版式张力（巨字出血/密度对比）③配给叙事事件/物件（开盒灯/手心 orb/拍纸条）
- **实现要点**：先定总预算再分配；每个动效报出它属于三形态中的哪一个
- **禁忌**：每个区块一个 reveal 的撒胡椒面

## T09 母题降级复用

- **来源**：CASE-006 cache 方块
- **同构性前提**：主视觉里存在一个最小的可识别单元。没有核心母题可降级的页面，先从概念里长一个出来，别借别人的方块
- **适用**：需要分隔/装饰但不想用 hr 和渐变
- **机制**：把核心 diagram 的母题**降级**复用到结构件——cache 方块从原理图复用为区块分隔线（一排小方块、中央一簇填充蓝）
- **实现要点**：找出主视觉里最小的可识别单元；把它降级（更小/更稀/单色）后用做结构件
- **禁忌**：升级为更大的装饰（那就成了堆砌）

## T10 双色极端 + 素材归化

- **来源**：CASE-007 hermes
- **同构性前提**：产品有极端性格，且全部视觉素材可控可归化。素材不可控（用户头像墙、真实彩色截图必须原样展示）时，淹没兜不住
- **适用**：敢用高饱和纯色淹没的场景
- **机制**：一个高饱和纯色铺满 100% 全底 + 所有视觉素材强制归化进双色纪律（照片 duotone、插画单色线刻、录屏画框装裱）
- **实现要点**：兜住高饱和的从来不是"少用"，是"归化"；逐素材检查归化方式
- **禁忌**：任何一张原图直出（一张彩色照片毁全场）

## T11 命名即概念种子

- **来源**：CASE-007 Hermes；同族 CASE-006"词的形式即词的内容"
- **同构性前提**：产品名有文化联想、且联想与产品机制同构（Hermes=信使=agent 成立）。名字是纯造词无联想时，换种子来源——从产品行为/领域黑话里找（006 的 cache-first 路线）
- **适用**：产品已有名字（尤其有文化联想的名字）
- **机制**：从产品名/语言事实长材质——Hermes=众神信使 → 铜版蚀刻 → 博物馆图录版式 → colophon 版记
- **实现要点**：写下名字的全部文化联想，选一个与产品机制同构的；从该联想推导材质全家桶
- **禁忌**：名字是神话却选了 cyber 材质——概念与材质脱钩

## T12 场景化 UI

- **来源**：CASE-008 GPT 档案桌（用户钦定：沉浸感+围绕场景展开）
- **同构性前提**：体验型产品，且数据模型里有非工具字段（牵挂/silence/tone）。工具型产品（SLA 字段：status/conf/latency）做成场景是新模板病——先过 CASE-009 的品类判断
- **适用**：体验型产品的功能界面（游戏/陪伴/叙事工具）
- **机制**：界面组织单位 = 场景物件，不是信息区块；每个 UI 元素找到场景内物理对应物（HP=伤口线、结果=拍上桌的纸条、日志=线圈笔记本、照片=拍立得"曝光不足"）
- **实现要点**：先定"用户坐在哪"（一张侦探的桌子前）；列全部 UI 元素逐个分配物理身份；**完备率自查**：找出一个穿帮元素就修（标准进度条/toast/原生滚动条都算）
- **禁忌**：物理对应物半套——90% 场景化 + 10% 原生控件 = 全盘出戏

## T13 单一材质 × 多氛围 register

- **来源**：CASE-009 Engine_Agent frontend v3
- **同构性前提**：多个场景是"同一个世界的不同时刻"，而非彼此独立的功能模块。场景是独立功能时，共享材质反而捆住手脚
- **适用**：需要多场景/多时段/多情绪切换的体验型界面
- **机制**：全部场景共享一个材质（信纸），切换的是氛围 register——光、色温、语气 tone（清晨五点/雨夜列车/停电以后）
- **实现要点**：材质变量锁死，氛围变量放开；每个 register 配一句语气文案（placeholder："灯灭了，她还在。"）
- **禁忌**：场景切换连材质一起换——那就成了 11 个皮肤，不是 1 个世界

## T14 结构转译

- **来源**：CASE-013 麦屿 Bakery（店名"屿" → 秋季物产图海图）；同族 CASE-007 Hermes → 神话图录、CASE-006 cache-first → 终端骨架
- **同构性前提**：概念有一个可命名的结构原型（地图 / 档案 / 仪器面板 / 标本册 / 单据）能承载页面上全部信息单位。概念只有一句 slogan、展不成结构时，硬做结构只是装饰
- **适用**：品牌海报 / 落地页 / 任何"概念要能落到每一层"的任务
- **机制**：把概念翻译成一套**可命名的结构件**——地名 / 编号 / 刻度 / 图例 / 图注 / 版记，然后让产品、价格、日期都变成这套结构里的物件；不是给元素加概念装饰
- **实现要点**：列一张"页面所有信息单位 → 结构件身份"对照表；有一个单位找不到身份，就说明概念还没落到底
- **禁忌**：概念只停在标题 / 文案 / 印章层——那不是转译，是贴标（对照：同题站内作品《一屿秋味》也用了"岛"，但只留在文案与印章；本案例把它做成了地图系统）
