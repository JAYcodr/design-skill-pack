# 验收：把"我检查过了"变成证据

> 交付前最常出现的假完成：代码写完 = 效果对了、长截图缩着看过 = 逐屏看过、我觉得没报错。CASE-012 的教训：决策说明写得漂亮不算数，产出物完成度才是秤。验收只留可复查的证据。

## 交付前四步（顺序固定）

1. **逐屏截图看**（红线③）：桌面 1440 宽 + 手机 390 宽；首屏、中间、结尾各至少一张；手机再单独看一遍。看图时问："这是作品还是作业？"
2. **跑事实检查**：
   ```bash
   python3 scripts/quick_check.py 成品.html
   ```
   硬伤清零（裂图、资源路径错、标题空）；警告逐条判断（字号过小、外链、占位残留、缺 viewport）。
3. **零报错 + 首屏可交互**：控制台无红色报错；按钮、链接、切换真的能点。没有浏览器能力时，在 `verify.md` 写「未验证（原因）」，不许写「已检查」。
4. **缩略图门**（仅转化任务）：缩到 300px 宽，读得出「品牌 / 日期 / 产品 / 价格」才算过。

## `verify.md` 模板

交付时连同成品一起给，不要只写"已检查"：

| 检查 | 证据（命令输出 / 截图路径） | 结果 |
|---|---|---|
| 控制台 | 无红错（截图 `shots/console.png`） | ✓ |
| 首屏可交互 | 点击主按钮正常（截图 `shots/hero.png`） | ✓ |
| quick_check | 0 硬伤 / 2 警告（警告 1：图注 10px，作品可接受） | ✓ |
| 手机 390 宽 | 无横向溢出（截图 `shots/mobile.png`） | ✓ |
| 缩略图 300px | 品牌/日期/产品/价格可读（截图 `shots/thumb.png`） | ✓ / 不适用 |
| 未验证项 | 声音、真实数据、真实设备手感 | 如实列出 |

路径写相对项目目录的路径，截图不要只存在自己脑子里。

## 脚本不检查什么（诚实边界）

- **控制台运行时错误**：静态检查看不到，必须真跑浏览器；
- **真实对比度**：脚本读不到渲染后的颜色，只能看代码里的字号；
- **视觉质量**：好不好看归人判，脚本不打分；
- **缩略图门**：300px 下读不读得出来，要人眼看。

脚本说"过"不等于能交；脚本没报的问题也不等于没有。

## 常见假完成信号

| 信号 | 实际发生了什么 |
|---|---|
| 只看整页长截图 | 字全糊了，字号/间距/断裂都看不出来 |
| 只读代码没跑页面 | 白屏、JS 报错、布局崩了没发现 |
| 占位没换 | Lorem、灰色占位块、`TODO` 留在成品里（quick_check 会报） |
| 题面缺段 | 要求的板块没做，复刻题只做四分之一 |
| "我觉得没问题" | 没证据；至少给一张截图和一个命令输出 |
