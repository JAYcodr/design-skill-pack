# 编排规范 —— 从 trending.json 到 curated.json

这一步决定晨报的质量。脚本能保证格式正确，但"选得准、分得清、说得明白"只能靠你。

---

## 一、筛选：从 ~150 挑到 40–60

### 排序基准

`trending.json` 已按 `today`（今日新增 Star）降序排好。这是主排序依据 —— 它反映的是**今天的热度**，而不是历史积累。一个 20 万星的老仓库今天只涨 7 颗星，不如一个 2000 星的新项目今天涨 190 颗星有新闻价值。

### 纳入标准

优先收：

- `today` 高的（尤其 >100）
- 有清晰 description 的（空描述的仓库很难写出好摘要，除非项目本身极有名）
- 总榜前 15 名 —— 无论涨星多少都值得给个位置，这是 GitHub 官方口径的"今日焦点"
- 主题上能撑起某个版块的 —— 如果某版块只有 2 条，就在候选里再挖几条相关的补上

主动剔除：

- 纯个人配置仓库（dotfiles、个人博客源码）、刷星农场、空壳仓库
- 描述完全无法判断用途，且仓库名也看不出所以然的
- 同一作者同一天霸榜多个雷同项目 —— 保留最有代表性的一个
- 明显的挖矿 / 灰产 / 破解版权内容

### 数量把控

- **40–60 条**是舒适区。低于 30 条显得单薄，超过 70 条读者会翻不动。
- 版块之间尽量别太失衡。理想是每块 8–14 条，最少的那块不要低于 5 条。
- 如果某天榜单主题高度集中（比如全是 AI Agent），不要硬凑五个版块，改成更贴合的划分，或者把版块名改窄一些（"Agent 运行壳" / "Agent 技能与工具"）。

## 二、归类：设计当天的五个版块

### 默认划分（AI 主题日适用）

| id | 名称 | 收什么 |
|---|---|---|
| `models` | 模型与多模态 | 语音 / 视觉 / 3D / 生成式模型的开源实现、推理引擎、硬件后端 |
| `agents` | Agent 与 AI 应用 | 编码 Agent、技能包、沙箱、Agent 治理、AI 驱动的终端应用 |
| `tools` | 开发工具与效率 | 编辑器、TUI、桌面效率软件、调试链路、MCP 服务 |
| `infra` | 框架与基础设施 | 语言运行时、后端框架、数据库、CI/CD、可观测性、自托管服务 |
| `learn` | 学习资源与精选清单 | 教程、开源书、课程、awesome 清单 |

### 划分原则

1. **按"读者关心什么"分，不按编程语言分。** 语言已经是卡片上的 chip 了，再拿它当版块就重复了。
2. **五个版块要互斥**。一个仓库只能进一个版块。边界模糊时，问自己"读者会去哪一栏找它"。
   - 例：`chrome-devtools-mcp` 是给 Agent 用的 MCP 服务 —— 但它本质是调试工具，进 `tools`。
   - 例：`bojieli/ai-agent-book` 是讲 Agent 的书 —— 但它是学习材料，进 `learn`。
3. **版块顺序有讲究**。把当天最有信息量的放前面。编号从第一个版块开始累加，读者从上往下读。
4. **`desc` 写一句话**，说清这个版块今天收了什么、有什么看点。别写"本版块收录相关项目"这种废话。

### 主题不匹配时怎么办

榜单不是每天都以 AI 为主。如果当天是别的主题，重新设计版块，例如：

- 前端日：框架与运行时 / 组件与 UI 库 / 构建与工程化 / 可视化与图形 / 学习资源
- 基础设施日：数据库与存储 / 云原生与编排 / 可观测性 / 安全与网络 / 学习资源
- 混合日：按"今日焦点 / 工具 / 框架 / 应用 / 资源"这种通用切法

`sections` 数组长度不强制是 5，但 3–6 个之间体验最好。模板内置 5 组配色，超过 5 个版块会循环复用。

## 三、写摘要：≤60 字的硬约束

这是整个流程里最容易翻车的地方。

### 三条铁律

1. **必须重写，不许直译。** 英文 description 是给开发者看的营销文案，直译过来又干又长。
2. **说清"是什么 + 解决什么问题"。** 读者扫一眼要能判断"这跟我有没有关系"。
3. **≤60 字**（按 Python `len()` 算，中文标点各计 1 字）。超了 `render.py` 会直接报错并指出是哪一条。

### 写法对照

原文：`Build local voice agents with open-source models`

| | 写法 | 问题 |
|---|---|---|
| 差 | 用开源模型构建本地语音智能体 | 直译，等于没说，读者不知道它到底给了什么 |
| 差 | 这是一个非常强大的语音项目，支持多种模型，社区活跃，值得关注 | 全是形容词，零信息 |
| 好 | 用开源模型搭建可本地运行的语音对话 Agent，串起识别、大模型与合成完整链路 | 说清了本地部署 + 完整链路这两个关键卖点 |

原文：`A curated list of awesome libraries, packages, strategies, books, blogs, tutorials for systematic trading`

| | 写法 |
|---|---|
| 差 | 一个精选的系统化交易资源列表 |
| 好 | 系统化交易精选清单，汇总量化库、策略、书籍、博客与教程资源 |

### 措辞习惯

- 用动词开头或主语开头，别用"这是一个……"
- 数字比形容词有力："21 节课"好过"内容丰富"
- 保留有辨识度的专有名词：Claude Code、MCP、昇腾 NPU、vLLM
- 不写"值得关注""非常强大""社区活跃"这类空话
- 句末统一用句号，或统一都不用，别混着来
- 描述为空的仓库：靠仓库名 + 语言 + 你对项目的既有认知来写；实在不认识就剔除，不要编

### 特别注意

**不要编造事实。** Star 数、Fork 数、语言全部来自抓取结果，直接搬。摘要里如果要提"微软出品""OpenAI 官方"，必须是 `repo` 的 owner 确实是 `microsoft` / `openai`。拿不准的功能细节就别写进去。

## 四、`src` 字段怎么填

标记这条是从哪个榜单来的，会渲染成蓝色 chip：

- 总榜条目：`总榜 #4`（带原始名次，来自 `trending.json` 的 `src` 字段，直接抄）
- 语言分榜：`Python 榜` / `Rust 榜` / `Jupyter 榜`（把 `trending.json` 里的 `python` 改写成中文友好形式）

## 五、自查清单

产出 `curated.json` 后，交给 `render.py` 之前先自己过一遍：

- [ ] 条数在 40–60 之间，最小版块 ≥5 条
- [ ] 每条 `s` 都能在 `sections` 里找到对应 `id`
- [ ] 所有 `sum` 都 ≤60 字，都是重写过的中文，没有空值
- [ ] `stars` / `today` / `forks` 是整数，不是字符串
- [ ] `repo` 全部是 `owner/name`，没有多余的路径或 URL 前缀
- [ ] 没有重复的 `repo`
- [ ] `captured_at` 是带 `+08:00` 的 ISO 串
- [ ] 版块 `desc` 都写了实质内容
- [ ] 没有编造的仓库或数据 —— 每条都能在 `trending.json` 里对上
